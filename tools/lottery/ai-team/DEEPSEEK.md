# DeepSeek 接入配置 v1.0

接入日期：2026-10-14
状态：已连接（实测通过）
密钥：存于系统保险柜（custom.deepseek），永不进仓库/聊天/日志

## 角色：代码审核员

| 事项 | 说明 |
|---|---|
| 能做 | 分析 PR diff、指出 bug、安全风险、代码风格问题，提修改建议 |
| 不能做 | 合并 PR、推送代码、部署、操作钱包、转移资金 |
| 模型 | 日常 deepseek-chat；复杂逻辑审核用 deepseek-reasoner |
| 调用入口 | 总指挥（Muse）统一调用，不直接暴露给仓库 |

## 权限边界

- 只读审查：DeepSeek 收到的是代码文本，返回的是文字建议
- 它没有任何仓库写权限、没有任何钱包权限
- 最终是否采纳建议、是否合并，由总指挥决定

## 调用配额

- 单次请求超时：60 秒
- 网络失败重试：最多 2 次（4xx 错误不重试）
- 单次 max_tokens：日常 50–2000，代码审核最多 8000
- 月预算上限：¥30（按 deepseek-chat 官价估算约 1500 万 tokens）
- 用量记录：~/workspace/skills/deepseek/usage.log（每次调用追加一行）
- 超预算时总指挥暂停调用并通知用户

## 审核流程（总指挥调用 DeepSeek 时）

1. 某 AI 提交 PR 到 dev
2. 总指挥取 PR diff，调 DeepSeek 审核
3. DeepSeek 返回问题清单
4. 总指挥按 REVIEW.md 做最终判定：通过 / 打回
