# 自动审核与测试流程 v1.0

总指挥（Muse）在合并任何 AI 的代码前，必须走完以下流程。

## 1. 静态检查（必须全过）

- [ ] JS 文件：`node --check <文件>` 无语法错误
- [ ] HTML 文件：以 `<!DOCTYPE` 开头；`<style>` 内大括号配平
- [ ] 单文件 ≤100KB（GitHub 推送上限），超了必须拆分
- [ ] 无硬编码密钥/私钥/助记词（grep 扫 `key`、`secret`、`mnemonic`）
- [ ] 图片走 .b64 文本 + fetch 拼 data URL，不直接推二进制

## 2. 规范检查

- [ ] 在正确的 feature 分支上，不是从 main 直接改的
- [ ] 只改了任务范围内的文件
- [ ] 中英文双语文案齐全（页面文案类任务）
- [ ] 版本号已 bump（改了被引用的 JS，index.html 里 `?v=` 同步加）

## 3. 链上相关检查（如涉及）

- [ ] 合约地址 44 位非法地址拦截（`cast call` 实调验证）
- [ ] 不涉及资金移动；如涉及，转自助操作清单给用户
- [ ] 票价/费率等参数与链上只读查询结果一致

## 4. 上线验证（用户说"上线"后）

- [ ] 推送返回 ok:true
- [ ] 新 blob SHA 与推送前不同
- [ ] curl 抓 raw 文件，内容关键字匹配
- [ ] HTML 以 `<!DOCTYPE` 开头（防 base64 坏文件重演）

## 5. 打回标准

以下情况直接打回，不合并：
- 静态检查任一项不过
- 改了任务范围外的文件且无说明
- 把用户原图换成 AI 图（铁律）
- 触碰安全红线

打回时在 HANDOFF.md 写明原因，任务状态改回"进行中"。
