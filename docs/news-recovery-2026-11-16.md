# 资讯页面恢复记录（2026-11-16，北京时间）

## 已核实的故障与范围

- `/news/` 使用 `https://count.web3origin.com/news/feed`。本次返回 12 篇公告、24 条推文；最新公告为 2026-09-20，最新推文为 2026-11-08。
- 响应的 `updatedAt=1794759466056` 对应北京时间 2026-11-16 00:17:46，`syncedBy=vps`。这个时间不能证明上游采集成功，也不能单凭旧内容断定定时任务已经停止。
- 旧页面只根据 `ok=true` 显示“数据源正常”，没有检查内容日期。刷新失败还会清空已经展示的资讯；一条推文日期异常也可能使整页进入失败处理。
- 官方页面脚本实际调用的 `https://origindao.io/index.php/addons/cms/api/arclist?model=5` 在浏览器中两次返回 `502 Bad Gateway`。脚本引用的旧备用域名 `originworld.org` 对同一路径返回 HTML 首页，不是公告 JSON，不能直接替换为可用数据源。
- 已登录站点后台的“官方 X 动态”是精选链接管理，当前清单为空；这不等于 `syncedBy=vps` 的独立采集任务配置为空，不能据此乱补数据。
- 当前仓库及检查过的 dev、feature/codex-platform-closure-20261020 分支没有资讯采集程序。现有连接未提供该 VPS 的采集配置、日志和部署入口。

## 本次页面修复

- 保持布局和原有操作入口。原状态位置按当前栏目显示内容的最新发布日期，统一为北京时间；超过 7 天仅提示“近期未收录新内容”，不凭时间推断采集失败。
- 请求禁用浏览器缓存，检查 HTTP 状态与数据格式，设置 12 秒超时并合并重复刷新。超时的旧请求不会覆盖后续成功结果。
- 刷新失败保留已经加载的公告和推文，原刷新入口和 90 秒轮询仍可重试。
- 按发布时间排序，容错处理异常时间、缺失正文和非数组媒体字段。过期公告、未来时间、无效时间不弹“最新公告”。

## 验证与后续验收

`tests/news-recovery.test.cjs` 的 8 项受控回归检查全部通过，覆盖接口失败、超时、旧响应、异常数据、内容保留、排序与通知。运行方式见 `tests/README.md`。

本次不代表后台自动采集恢复。继续修复需要实际资讯采集程序或其服务器管理入口：核对最近执行日志、公告源响应、X 来源权限/额度/账号变化、翻译步骤以及写入 feed 的结果。应分别记录尝试时间、成功时间和最新内容时间；失败时保留最后成功数据。最终需验证一条真实新资讯经过采集、保存并出现在本站，才能确认自动更新恢复。
